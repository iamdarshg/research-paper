\section{Validation and Testing Standards}
\label{sec:validation}
To keep validation claims bounded, we separate three levels of evidence:
\begin{itemize}
    \item \textbf{Code-path validation:} the training, generation, cleanup, export, and CFD scoring routines run end-to-end in this environment.
    \item \textbf{Solver validation:} the built-in CFD path can be compared against a higher-fidelity external solver when one is available.
    \item \textbf{Physical validation:} the generated shape should eventually be compared against analytic or experimental benchmarks, which is still future work.
\end{itemize}

\subsection{Verification}
Verification checks that the implemented steps are executed as intended. In this revision we verified that:
\begin{itemize}
    \item the shape-plausibility loss is included in the training objective,
    \item the connected-component cleanup hook removes smaller disconnected voxel components,
    \item STL export succeeds from the cleaned voxel grid, and
    \item the OpenFOAM export hook writes a runnable case directory skeleton, including \texttt{blockMeshDict}, \texttt{snappyHexMeshDict}, and surface STL output.
\end{itemize}

\subsection{Validation}
The OpenFOAM export path is runnable in principle, but OpenFOAM was not installed on the host used for this revision. External comparison numbers therefore come from a frozen, dated corpus and are reported as inherited artifacts, not as a fresh local solver run. The corrected comparison convention is documented, but the corpus does not establish external agreement: only 1/16 sonicFoam rows and 0/14 simpleFoam rows meet the repository's 5\% threshold. A fresh OpenFOAM comparison must report residual histories, force-history stability, convergence, boundary conditions, and the post-fix solver version before it can support a validation claim.

The paper therefore claims only that the export path and comparison tooling exist, and that the measurement-integrity audit exposes the current disagreement and its normalization sensitivity. It does not claim a direct validated solver-to-solver result from this revision.
