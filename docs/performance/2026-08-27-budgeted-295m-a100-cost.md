# Budgeted 295M / 128^3 training estimate

Date: 2026-08-27  
Preset: `CLI/config.yaml` 295M model, 128^3 lattice, 8,027-shape corpus, 12 epochs  
Purpose: keep the planned run at or below the user's $120 A100 Spot ceiling.

## What is measured

The local A100 artifact `a100-20260826T124558Z/benchmark.jsonl` measured the
295M coordinate converter (not the full trainer) on an NVIDIA A100-SXM4-40GB:

| Work | Rows | Chunk | Measured time |
|---|---:|---:|---:|
| Sparse converter update | 65,536 | 8,192 | 0.669 s |
| Full-lattice converter update | 2,097,152 | 65,536 | 20.313 s |

Those runs include converter forward/backward and optimizer work for the
converter, but not the diffusion stack, CFD, data loading, or checkpoint sync.
They are therefore a lower-bound measurement for a complete training update.

## Budget schedule

The checked-in budget preset uses:

| Setting | Value | Reason |
|---|---:|---|
| Optimizer updates | 7,716 train records x 12 epochs = 92,592 | Current training split |
| Sparse coordinate rows | 65,536/update | Keeps positive/negative stratification while reducing converter work |
| Exact full-lattice anchor | Every 64 updates | Retains the exact loss but reduces its amortized cost |
| Direct CFD interval | Every 32 updates | Preserves the 5-step solver objective on scheduled updates |
| SPSA directions | 8 | Half the previous 16-direction probe count |
| Direct probe batch | 4 | Intended A100-class setting; L4 gate remains at 1 |
| Stream/BFL backend | fused, 512-thread blocks | Removes the 27-roll reference streaming path on CUDA |

## Cost arithmetic

Converter-only time for 12 epochs:

```text
sparse = 92,592 x 0.669 s                         = 17.22 h
full   = (92,592 / 64) x 20.313 s                 =  8.16 h
converter floor                                       25.37 h
```

At the current official A100 40GB Spot rate of $2.12081/hour, that measured
converter floor is approximately **$53.81**. The full trainer still needs to
fit inside the remaining **$66.16**, or 31.20 A100-hours.

An intentionally conservative operating allowance of 1.0 additional second per
optimizer update for the diffusion stack, CFD, CPU preparation, checkpointing,
and normal scheduling overhead gives:

```text
additional = 92,592 x 1.0 s                       = 25.72 h
projected total                                      51.09 h
projected Spot compute                              $108.36
```

A 10% interruption/restart and measurement uncertainty reserve gives about
56.20 hours and **$119.19**. This is a planning bound, not an end-to-end A100
benchmark; the run must still perform a short production-faithful timing gate
before committing to all 12 epochs.

## Acceptance gate before the final run

The final run should not start until one A100 Spot update (after warmup) shows
an amortized wall time at or below:

```text
$120 / $2.12081 per hour = 56.58 h available
56.58 h / 92,592 updates = 2.20 s/update
```

The new schedule's measured converter contribution is about 0.986 s/update
before the exact-anchor frequency is considered separately; the remaining
budget is about 1.26 s/update for the complete diffusion, CFD, I/O, and retry
path. If the production-faithful gate exceeds 2.20 s/update, the safe next
knob is to reduce the exact anchor frequency to every 128 updates or reduce
the sparse coordinate rows to 32,768. No claim about quality should be made
without comparing the held-out geometry metrics against the previous schedule.

The A100 Spot price used here is the official Google Cloud price observed for
the `a2-highgpu-1g` family on 2026-08-27. Storage and egress are not included;
the input archive is already in the project bucket and the watchdog must stop
before the compute cap rather than spend the reserve on retries.
